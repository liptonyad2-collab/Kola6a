# План разработки Kola6a CRM

## Зафиксированные решения
- Пять направлений: Домики, Пляж, Развлечения и водный транспорт, Дополнительные услуги, Аренда территории и мероприятий.
- Каждая продажа детализируется по услуге, отчёт агрегируется по категориям и направлениям.
- Цены: базовые, сезонные, по времени и индивидуальные; фактическая цена сохраняется в продаже.
- Продажи в основной CRM вносит **только администратор**.
- Роли: owner, admin, employee, accountant, manager.
- Источники существующего учёта: Telegram, таблицы, бумажные отчёты, банк, касса/сейф, BookMeNow.

## Фаза 1 — рабочий фундамент
1. [x] Каркас веб-приложения и интерфейс каталога (демонстрационные данные).
2. [x] Начальная SQL-схема (ещё не развернута в облаке).
3. [ ] Подключение облачной базы и хранение секретов на сервере.
4. [ ] Авторизация и проверенные серверные права для пяти ролей.
5. [ ] CRUD для направлений, категорий, услуг и цен.
6. [ ] Тесты сценариев доступа.

## Фаза 2 — продажи и движение денег
1. [ ] Создание и подтверждение продаж только администратором.
2. [ ] Сезонные и временные тарифы; контроль изменения цены.
3. [ ] Раздельное хранение продажи, платежа и распределения платежей.
4. [ ] Предоплаты, частичная оплата, возвраты, кассы и сейф.
5. [ ] Дневные отчёты, сверка и история исправлений.
6. [ ] Ограничения на распределение средств и двойной учёт на стороне БД/сервера.

## Фаза 3 — бронь
- Ресурсы и календарь.
- Недопущение пересекающихся броней.
- Клиенты, заезды/выезды, мероприятия.

## Фаза 4 — интеграции
- Импорт XLSX/CSV с предварительной проверкой.
- Telegram: разбор отчёта только с подтверждением администратора.
- BookMeNow: сначала проверить API или экспорт.
- Банк: импорт выписок и сопоставление с продажами.

## Фаза 5 — аналитика
- Детализация выручки, расходов и движения денежных средств.
- Определение методики расчёта прибыли и сверка.
- ИИ-аналитик на подтверждённых данных.

## Открытые вопросы
- Точные тарифы, сезоны, перечень реально активных услуг.
- Методика расчёта прибыли (кассовый метод/начисление).
- Доступность BookMeNow API и банка.
- Учёт НДС/налогов, возвратов и комиссий.
- Количество физических ресурсов и сотрудников.

## Принципы безопасности
Прототип не подключён к боевым данным. RLS в базе включён без разрешающих политик; сначала реализовать серверные проверки. Нельзя публиковать секретные ключи, реальные данные клиентов и банковские реквизиты в GitHub.
